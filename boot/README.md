# USB CDC

NUCLEO-F439ZI（MB1137）的 USB OTG FS 初始化、CDC 设备枚举和原始字节回显示例。

- 时钟：8 MHz HSE bypass（ST-LINK MCO），168 MHz SYSCLK，48 MHz USB。
- 接口：CN13 用户 USB，PA11 为 D−，PA12 为 D+；通过 CN1 给 ST-LINK 供电以提供 MCO。
- 设备名：`STM32F439 USB CDC`；开发用 VID/PID：`16C0:27DD`，序列号使用芯片 UID。
- `src/main.rs` 配置时钟，`src/usb.rs` 配置 USB 并持续调用 `usb.poll`。

在本目录执行 `cargo run --locked -j 1`，通过 ST-LINK 烧录运行。

## 示例写在哪里

收发示例已经放在 `src/usb.rs` 的 `run()` 函数内，不需要复制到 `main.rs`。
执行顺序为 `main()` 配置时钟 → `usb::run()` 初始化 USB → `loop` 中轮询、接收和发送。

循环中的第 2 步是电脑到板子的接收，`Ok(count)` 分支中已标出接收处理的位置，本次有效数据是 `&buf[..received]`。
第 3 步是板子到电脑的发送，当前把收到的字节原样发回；以后可以在这里换成自己的回复，并继续保留部分发送和 `WouldBlock` 的处理。
缓冲区和发送进度变量在循环外定义，以便跨循环保留数据。

## 在电脑上试一下

1. 运行固件，通过 CN13 连接电脑，打开 `STM32F439 USB CDC` 对应的串口。
2. 串口工具可设为 115200 / 8N1，关闭硬件流控和本地回显；本地回显关闭后，显示收到的字节才是板子发回的数据。
3. 发送 `hello`，接收区应出现 `hello`；发送换行字节也会原样返回。
4. 此示例没有欢迎文字，打开串口后需要先从电脑发送数据。

USB CDC 是字节流，一条消息可能分多次 `read` 收到。后续写 CLI 时，需要自己累计字节并按换行等规则判断命令结束。
当前只演示收发，不包含命令解析或启动业务；硬件行为需要上板验证。
